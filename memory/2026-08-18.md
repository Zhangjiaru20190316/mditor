## mditor 批注修复（v3.6.5 工作区，未提交）

用户反馈两个问题，均已修复并验证（vitest 118 全过 / tsc / eslint 干净 / 浏览器 harness 13/13）：

1. **批注徽章点击不灵**：根因是 `useAnnotations` 的 150ms 防抖列表过期——文档刚变化（新建批注、切文件、AI 写回）后点徽章，`AnnotationPopover` 查不到 id 就立即 close，表现为点击无反应。修复：点击时用 `parseAnnotations(markdownRef.current)` 现场解析兜底（fallback state）；"批注消失"关闭逻辑也改为现场解析确认后才关。次因：徽章 16×16 命中区小，CSS `::after inset:-4px` 扩大。
2. **代码块批注竖向堆叠**：每个标记独占一段（`insertAnnoMarker` 代码块分支）。修复为纯渲染层：`stampAnnotationMarkers` 给"只含标记"的段落打 `anno-row-item` 类，CSS `display:inline` 使连续标记段流入同一行、满行换行。不改 markdown 源（`resolveCodeLines` 要求标记独占一行源文本，用户确认过此约束并选择仅改渲染层）。

改动文件：`AnnotationPopover.tsx`、`useAnnotationMarkers.ts`、`annotation.css`（工作区另有 4 个文件的 sv 平滑滚动未提交改动，未触碰）。

## mditor 批注修复第二轮（v3.6.6 工作区，未提交）

用户反馈：AI 批注代码块的徽章点不到；普通徽章经常要点两次。诊断出四个根因并全部修复（vitest 121 全过 / tsc / eslint 干净 / 真实 crepe 端到端 harness 25/25）：

1. **元数据前缀定义被 Milkdown 解析整个丢弃**（主根因，实测实锤）：`[^id]: <!--md:line…-->内容` 过不了 crepe 解析往返——定义消失、徽章成孤儿（渲染但点不开），且 nextAnnotationId 复用 id。修复：`withCodeLineMeta` 把令牌写到首行行尾（`内容 <!--…-->`），`stripCodeLineMeta` 兼容读旧前缀形态。**旧文档（前缀形态）在富文本模式保存时定义仍会丢——编辑该批注会自动迁移为新形态（updateAnnotationInMd 重写定义行），属已知遗留**。
2. **ProseMirror 给纯标记段落塞 `<img.ProseMirror-separator>` + `<br.ProseMirror-trailingBreak>`**，导致第一轮的 anno-row-item 打类在真实编辑器从未生效（横向排版其实没生效过）。修复：isMarkerOnlyParagraph 忽略这两类辅助节点。
3. **弹窗卡片遮挡相邻徽章**（"要点两次"主因）：380px 卡片盖住相邻徽章，点击命中卡片被忽略。修复：placeCard 候选位置（右/左/右下/左下）+ 其他徽章矩形碰撞检测择优。
4. **孤儿徽章静默失败**：点击后两路解析都 miss 时什么都不显示。修复：60ms 重试（覆盖 rAF 镜像滞后）后仍缺失 → 渲染"内容缺失"卡片（可删残留标记）。
5. 附带：resolveCodeLines 容忍同行前置 `[^anno-*]` 标记（sv 连续批注丢行锚）；AiPanel annotatingId 在面板关闭/重开时复位（防"精炼中…"永久禁用）。

改动：`codeAnno.ts`(+test)、`annotations` 无、`AnnotationPopover.tsx`、`useAnnotationMarkers.ts`、`AiPanel.tsx`。上轮的 4 个 sv 平滑滚动文件用户已自行提交（版本 3.6.6）。

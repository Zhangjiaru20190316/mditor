### 关键决策与教训

1. **cargo 代理坑（重要）**：本机 Windows 系统代理配了 127.0.0.1:7890（Clash，当前没开），cargo 的 libcurl 会读系统 ProxyServer（即使 ProxyEnable=0）直连失败。解法：`NO_PROXY='*' no_proxy='*' cargo ...` 绕过。直连 crates.io 本身是通的。
2. **object_store 停在 0.13 不能用 0.14**：0.14 的 aws feature 硬依赖 aws-lc-rs（Windows 要 NASM/CMake，本机没有）；0.13 用 ring 无需额外工具链。0.13 的 API：get/head/delete 在 `ObjectStoreExt` 扩展 trait（0.13 重构），PutMode/PutOptions 在 crate 根。
3. **WebCrypto 没有 MD5**（subtleCrypto 只支持 SHA 系）——规格里的「本地 md5 vs 远端内容型 ETag」判同不可行；改为冲突发生时直接字节比对（双侧字节本来就要读，语义更强）。manifest 的 md5 字段保留恒 null。
4. **单侧超限会误删对端**：>50MB 只过滤本地侧会让矩阵判 L=deleted→删远端。解法：超限键「冻结」（suspended 集合）——双侧都不参与判定、记录原样保留。有单测锚定（防误删红线）。
5. **矩阵的 absent 第 5 态**：规格 4 态无法表达「无记录且不存在」（首同步单侧新增文件）；引擎引入 absent：new×absent=upload、absent×new=download、其余不可达格冲突兜底。规格 4×4 矩阵 16 格逐格实现。
6. **base64 上传通道**：Tauri 2 JSON IPC 无二进制参数通道，s3_put 走 base64（Rust 手写解码，无第三方依赖）。md 文件为主可接受；SYNC-TODO 已标注。
7. 验收 9（多窗口手动同步转发）实现为统一 emit("sync-request")：doc 窗口与 main 同一条路径，main echo 由互斥挡住。
8. 工作区有上一会话的 mathNormalize/imageManager WIP（未提交）；remarkMathGuard.test.ts 有个未用变量挡了 tsc，做了最小修复（删一行）。tauri.conf.json 的 img-src 放宽（https: http:）也是上会话的改动，非本轮；connect-src 未动（同步 CSP 零变更达标）。

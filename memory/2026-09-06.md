教训/坑：
- **node_modules 半补丁态是本次最大的坑**：A/B 还原 → `npx patch-package`（apply 模式，对已打补丁的 node_modules 会因 code-block hunk 已在位而报错）→ 手动 python 重放断言失败——三步交错后文件停在「注释在、return false 还在」的半状态，导致绿腿假红。插桩 prosemirror-view 打决策日志（`spec.result=false contentEq=true`）才识破。以后 A/B 必须以「文件最终形态 grep 断言」收尾。
- patch-package 两种模式别混：regen（`npx patch-package <pkg>`）对比 node_modules 现状 vs 干净包生成补丁；apply（`npx patch-package`）只在干净 node_modules（如 npm ci 后）用。
- PM 视图复用机制速查：普通块 = NodeViewDesc.update（1470，sameMarkup 即原位补装饰）；自定义视图 = CustomNodeViewDesc → spec.update 说了算；`matchesNode` 要求 node.eq + 装饰相等；`updateNextNode` 只救 NodeViewDesc。纯 PM 实验证实 node 装饰变化对普通块是原位补丁（不重建）。
- jsdom 会清洗非法 CSS：style 哨兵要用合法自定义属性（`--probe-cv: 1`），裸 `probe-cv` 会被 style sanitizer 丢掉。
- vitest 测试里用 node:fs 要走动态导入 + @ts-expect-error（tsc lib 不含 node 类型是仓库约定）。

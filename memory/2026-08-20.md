## mditor v3.9.3：批注四大问题根修（盖章战争实锤）+ 诊断体系

用户报告四个重大批注 bug：①批注代码块后下方代码块一直闪 ②徽章不显示数字且悬停闪烁 ③侧栏跳转不落位 ④弹层不跟随移动。多轮修复未果，按系统化调试纪律（先实证后修复）+ 诊断工程化，全部根修。

### 真根因：盖章管线 ↔ ProseMirror DOM 同步的 17Hz 死循环（Bug ①②共享）

浏览器 harness（真实 Crepe + 真实 ops 完整生命周期）实测：**空闲 6 秒里徽章 `<sup>` 被重建 100 次（=1000/60ms 防抖周期，严丝合缝），marker 段落 class 翻转 100 次 1:1 对应，而 PM 事务数为 0**。机制：往 PM 管辖 DOM 写 `data-anno-num`/`anno-row-item` → PM DOMObserver 视为外来突变 → 从 toDOM 防御性重渲染（写入被抹）→ 我们的 MO 看到重建 → 60ms 后再盖章 → 永动。徽章无编号、悬停闪烁、marker 段落 17Hz 块↔行内振荡（下方代码块连片闪的驱动源，与流式无关故手动批注后也发作）全部由此解释。此循环自 stamp 体系诞生就存在，前三轮全在查流式/setValue 方向——查错了方向。

**根修**：`withPmObserverPaused`（annoDebug.ts）——盖章写入包进 `view.domObserver.stop()/start()`。prosemirror 内部 API（d.ts 未公开，结构化类型防御访问）：stop 期间写入零 MutationRecord，start() 会 takeRecords() 丢弃挂起记录，PM 完全看不见。useMilkdown 每次重建重绑；未注册直通降级。实测空闲重建 100→0。

### 修复清单

1. **B2 编号内建化**：包装 `footnote_reference.spec.toDOM`（spec 是普通可变对象，`this.spec = spec` 构造直赋）注入 data-anno-num——编号随 DOM 创建即存在，重建零延迟。战争中编号也常驻（harness 实证）。
2. **B1 断路器**：no-parse 永不整篇回退（整篇走同一解析器，下帧同形态必再失败——v3.9.2「3 帧自愈」在持续失败形态=1/3 帧率整篇死循环）；no-def 自愈至多一次再降级。annoHealRef 替代 annoFailStreakRef。
3. **解析器形态矩阵**（harness v2）：12 种体 × standalone/全文/往返三态**全部通过**——v3.9.2 的 no-parse 假设对这些形态不成立！断路器仅作防御。教训：v1 的 FAIL 全是我比较方法的 bug（textContent 无列表标记 `- `；序列化器还把 `- ` 转 `* `）。
4. **文末 `<br/>` 污染根除**（harness 复现）：定义插入落 content.size 在 crepe trailing 空段之后 → 旧空段滞留为顶级 `<br/>`——用户真实文档的堆积由此产生。`defInsertPos` 跳过全部 trailing 空段再插。
5. **B3 跳转**：`blockAbove`（文本）+ `codeBlockForMarker`（DOM，统一入口）都跳过 marker-only 行/段落——同块第 2+ 条批注的「上方」是别的标记段，此前解析/高亮/锚定全落空；`resolveCodeLines` 增 `blockIndex` 打通两空间；跳转光标停靠 + smoothJump 350ms + `annoHandoff` 低频预解析（防抖列表滞后时首击仍有 codeLine）。**坑**：徽章 sup 内含 "anno-N" 文本（font-size:0 隐藏），isMarkerParagraph 用 textContent 判空必失败——要逐子节点判定（对齐 hook 的 isMarkerOnlyParagraph）。
6. **B4 弹层 rAF 锚点跟随**：打开期间每帧只读锚点一个 rect（<1px 零开销）；纯主滚动算术平移，其他位移源（面板拖拽改 CSS 变量、.cm-scroller 横滚不冒泡、盖章/图片布局位移）全量重测。关闭即停。实测滚动 -120px 精确跟随。
7. **B1b 高度锁判定不必要**：战争灭后 CM 子块空闲期零抖动（cmBlockChildMut 冻结），按数据跳过，避免新 DOM 写入风险。

## mditor v3.9.4：滚动三大疑难修复 + 滚动诊断体系

用户报告：①滚动偶现乱闪/页面自己动 ②滚动卡顿 ③批注弹层随滚动盖住上下栏。要求系统排查 + 工程化调试设施。两个 Explore agent 并行全链路调查 + 主线程逐行核实。

### Bug③ 根因（代码层实锤，已修）

`.anno-popover` fixed z-index:70 挂在无层叠上下文的 `.app` 下；titlebar 只有 z-index:10，**tabbar/sb-status 根本没有 z-index**。rAF 跟随 `prev.top + delta` 无任何钳位。三管齐下修复：①三栏升 chrome 层 z-index:85（grid item 无需 position 即生效，仍低于菜单 90/弹窗 100）②placeCard 加 bounds 参数（动态量三栏高度，焦点模式自动退化）③跟随平移经 clampTop 钳位（卡片钉栏内等锚点回来）。坑：placeCard 兜底原本只把 top 往下压（防下溢），漏了抬上来（防进上栏）——测试抓到，补 `if (top < topMin) top = topMin`。

### Bug② 卡顿主源（弹层打开时，已修）

旧 rAF 跟随只在「锚点位移≈scrollTop 增量」才算纯滚动，否则全量 remeasure——remeasure 对全文档每徽章 getBoundingClientRect，**c-v:auto 大文档上强制离屏块逐个布局**；滚动中任何高度重估使锚点位移偏离 scrollTop 增量 → 掉进 remeasure → 掉大帧 → 下帧偏得更多 → 恶性循环。重构：横向零位移一律算术跟随（零测量），仅横向位移（面板拖拽）才 remeasure；remeasure 大文档只测视口±600px 顶层块的徽章（块级框尺寸对 c-v 已知，测块不布局子树）。

### Bug① 嫌疑修复 + 未盲修部分（诊断先行）

已修：打字机让位从 wheel 350ms 黑out → **滚动静止检测**（scroll 事件时间戳，静止 400ms 恢复）——wheel 盖不住惯性期（WebView2 惯性 >350ms 常见），黑out 截止后 selectionchange 居中与惯性对拉 =「自己动」；scroll 让位天然覆盖惯性全程 + 键盘滚动，且居中自己写 scrollTop 触发 scroll 自我抑制一拍防自激。
刻意未修：content-visibility 高度重估（3em 占位 vs 实际）、图片加载位移——**无运行时证据不盲修**（前几轮教训）。

### 滚动诊断体系（scrollDebug.ts，对齐 annoDebug 风格）

- **滚动会话归因**：滚动从静止转动的第一帧判发起者——用户输入 200ms 内→user；已知写入 250ms 内→write:tag（typewriter/outline-jump/anno-jump/search-jump/rebuild-restore/heal-restore/sv-jump 全打点）；都不是→**ghost（自己动实锤）**附最近写入。惯性归属发起会话（持续位移不重判）

- window.__scrollDebug 出口；诊断面板（Ctrl+Alt+D）升级：批注+滚动事件按时间合并 + ghost 摘要区 + 复制报告含滚动证据

Ctrl+Alt+D 开面板 → 滚动复现「自己动」→ 看 session:ghost（有 tag=打字机/跳转类已修路径吗？）、layout:shift（位移量与方向）、layout:height（高度跳变与 shift 同帧？）→ 若 c-v 高度重估实锤：候选修法是给顶层块固化实测 contain-intrinsic-size（首次布局后写回实际 px）或重新评估 overflow-anchor（盖章战争已根修，当初关锚定的放大器已不存在）。

## mditor v3.9.6：关闭/退出必然能关（v3.9.5 关闭拦截的兜底加固）

用户报告 v3.9.5 打包后「无法关闭软件」（点 X / Alt+F4 关不掉）。静态分析 + 上游实证：Tauri v2 在 Windows 上存在异步 close-requested 监听时窗口不会自行完成关闭、`destroy()` 在收尾中被吞/挂起的已知不可靠记录（d2r-desktop PR #99/#101、epicenter #550 等）。v3.9.5 的「无脏不拦截保持原生路径」+ 只靠一次 `destroy()` 正是最脆的两点。

### 修复（App.tsx 关闭路径整体加固）

1. **一律接管**：`onCloseRequested` 不再「无脏就放手」，统一 `preventDefault()` → 收尾 → `forceClose()`。Tauri 行为不确定性下不再赌原生路径。
2. **forceClose 双保险**：`destroy()` 后 1s 进程仍在 → `exit(0)`（保存已完成，强制结束不丢数据）；exit 再失败 → 二次 destroy。
3. **落盘 3s 硬上限**：`flushDirtyTabs` 包 `Promise.race` 超时——任何一步 IPC 挂起都不能锁死关闭，超时按「保存失败」走确认（自动保存 30s 兜底，最坏丢 30s 编辑）。
4. **重入防护**：`shutdownInFlightRef`——收尾期间第二次关闭请求（Alt+F4/再点 X）直接忽略，防并发弹窗/并发 destroy。
5. **全程 try/catch**：回调任何异常（动态导入、序列化抛错）→ `noteOpError("window-close"|"menu-exit"|"shutdown-flush"|"shutdown-confirm")` 记录后仍强制关闭，绝不留「静默关不掉」状态。弹窗异常视为确认继续关。
6. 菜单「退出」同序列 + exit 失败退回 forceClose。

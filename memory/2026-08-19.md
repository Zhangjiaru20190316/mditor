## mditor 批注全生命周期零整篇重写（v3.9.1 工作区，未提交）

用户反馈：批注代码块内容**整个流程都在闪**（创建/流式/收尾/删除）。诊断：v3.9 只修了流式帧（updateAnnotationBody 定点替换），但创建（addAnnotation→setValue 整篇）、收尾（aiWriteFinalize 整篇替换×2）、删除（removeAnnotation→setValue 整篇）仍整篇 replaceAll——每次整篇替换都会把全部代码块的 CodeMirror 子编辑器（CodeMirrorBlock node view）销毁重建（先纯 <pre> 占位再初始化 CM），即闪烁。

修复：新建 lib/annotationOps.ts（ctx 级定点事务，facade 与 harness 共用）：
- appendDefinitionOp：文末 tr.insert 定义节点（不 closeHistory，与 marker 插入合并一步撤销）
- replaceDefinitionOp：抽取原 updateAnnotationBody 逻辑（流式/编辑共用）
- finalizeAnnotationOp：baseline 无痕还原定义节点（addToHistory:false）+ next 单事务 closeHistory 写入，两步都只动定义区间，一次 Ctrl+Z 仍回 baseline；流式期间用户别处编辑被保留（优于旧整篇回卷）
- removeAnnoOp：单事务删定义 + 全部同 id 引用 + 因此变空的 marker 段（对齐 removeAnnotationFromMd 语义）

接线：facade 新增 appendAnnoDefinition / finalizeAnnotationBody / removeAnno（sv/失败返回 false → 调用方回退旧整篇路径当安全网）；Editor 三处改定点 + 流式回退 console.warn 诊断。

验证：vitest 149 / tsc / eslint 全绿；浏览器 harness（真实 crepe + headless Edge dump-dom，用完即删）跑完整生命周期（append → 流式×5 → finalize → remove）**10/10 通过**：代码块 .milkdown-code-block 元素引用全程不变 + 整篇替换事务计数 = 0。

教训：TS 对回调内赋值的 let 变量收窄会变 never（if (!x) return 后仍报错）——用独立函数返回 const（findDefinitionRegion）绕开。

## mditor 批注两问题修复（闪烁跳动 + 点两次，v3.9.1 并入）

用户报告：①代码块批注生成徽章过程界面乱闪乱跳 ②普通徽章点击经常要 2 次。三个 Explore agent 并行排查（徽章管线/点击链/未提交改动盘点）+ 主线程逐行核实，根因全部实锤：

问题①（闪烁）三层叠加：
1. **收尾定点化是死代码（主因）**：onAnnotateReply 的 baseline 捕获于 addAnnotation 之前，finalizeAnnotationOp 偏要从 baseline 里找本批注定义 → 永远 false → 每次收尾回退 aiWriteFinalize 整篇替换×2 → 全部 CodeMirror 子编辑器重建两遍。教训：harness 10/10 通过不代表真实调用链生效（harness 的 baseline 取法与 App 不同）
2. 60ms 未盖章窗口：marker 段先块级（44px）渲染、防抖盖章后才 inline 化（24px）→ 布局塌陷 + scroll anchoring 补偿 = 双跳；徽章数字同窗口晚到
3. 流式每帧 replaceDefinition 重置 60ms 防抖 → 盖章饥饿整个流式期

修法：finalize 重写为「无痕删批注落点 + closeHistory 原位放回」（不依赖 baseline，撤销契约不变）；insertAnnoMarker dispatch 后同步 stampAnnotationMarkers（幂等）；stamp 防抖加 250ms maxWait；.mditor-editor-host overflow-anchor:none。

问题②（点两次）三层叠加：
1. mousedown 处理器内同步 parseAnnotations(getMarkdown())（大文档 50-200ms 冻结，吞掉第一击反馈）
2. 双源 miss 时渲染门 return null → 60ms 空窗零反馈
3. placeCard 兜底钳位可盖住被点的锚点徽章 → 下一击落在卡片上被 contains 守卫吞掉

修法：解析挪到渲染后 effect（onDown 只信防抖列表）；!active 立即渲染「正在解析批注…」壳；打开兜底与消失关闭合并为单一解析 effect（resolvedRef 区分：显示过再消失→关闭，从未解析到→孤儿卡）；placeCard 抽 lib/popoverPlace.ts 纯函数，锚点自身纳入避让集 + 兜底强制垂直避让，7 例单测锁定。

自查补刀：finalize 第②步插入坐标基于删除前文档，同一批注多 marker 时需按「前方已删区间长度」折算（removedBefore），已修。

验证：tsc/eslint 0、vitest 157/157（新增 popoverPlace 7 例）、vite build 过。最终安装包 Mditor_3.9.1_x64-setup.exe 重建包含全部修复。

## mditor v3.9.2：特定文档批注流式闪烁根治（徽章无编号 + 下方代码块连片闪）

用户报告（v3.9.1 后）：鼠标放徽章上闪烁且不显示编号，标记段下方一段区域的代码块闪烁，但被批注的那个代码块（标记段上方）不闪——**只在 `E:\科研\tasks\final_task\Week8_结题项目搭建教学.md` 稳定复现**（该文档：anno-11 等多行 bullet 定义体 + <!--md:line--> 元数据 + 文末定义区插多个顶级 <br/> + anno-5 双引用）。AskUserQuestion 用户未答，按机制推断推进。

三个 Explore agent + 主线程逐行核实的机制事实（都有代码出处）：
- 徽章编号唯一来源是 stamp 的 data-anno-num（CSS attr()）；stamp 幂等无状态不自激 → **编号消失 ⟺ <sup> 被 PM 重建后 60ms 内又被重建**
- 非活跃代码块从不被盖章/高亮管线改写 → 它们闪 ⟺ CodeMirrorBlock 节点视图被大范围替换事务整建
- PM updateChildren 前缀/后缀预匹配：标记段与文末定义之间的一切都在重排跨度内 → 几何完全吻合「标记段以下闪、上方不闪」
- **实锤缺陷**：Editor.updateAnnotation 流式帧定点失败（中间态解析不出 footnote_definition）→ 每帧整篇 setValue → replaceAll → 全部 CM 块+全部徽章连根重建。失败与否取决于内容 → 只在特定文档复现
- **连环坑**：withCodeLineMeta 对首行为空的体回退「前缀 <!--md:line-->」形态，该形态定义被 Milkdown 解析器整个丢弃（codeAnno.ts 注释自己记录过）→「解析失败→整篇回退→定义消失→再回退」每帧循环

修复（annotationOps/useMilkdown/Editor/App/codeAnno/AnnotationPopover）：
1. replaceDefinitionOp 返回 TargetedOpResult（no-def/no-parse/surface）
2. updateAnnotation 加 transient：流式帧失败**跳帧**（收尾 finalizeAnnotation 权威写入），绝不整篇回退；同 id 连续 ≥3 帧失败才整篇自愈一次；限频 warn（2s/条，带原因）
3. withCodeLineMeta：首行为空 → 令牌挂第一条非空行尾；全空体宁可不写令牌，绝不产出前缀形态
4. 高亮链路收窄：restore 的「仍已涂色」只查 active marker 块；popover 锚点取 active 块内高亮行（activeHighlightAnchor）；解析 effect 补齐 scroll:false

验证：tsc/eslint 0、vitest **161/161**（+4：anno-11 真实体 buildDefinition 形态/round-trip 幂等、前导空行令牌位、空体存活性）、vite build 过。3.9.2 四件套 + CHANGELOG 已更，安装包重建。

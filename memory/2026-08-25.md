## mditor v4.4.0：多根工作区（VS Code 式 Multi-root Workspace）

用户诉求：不同工作区之间切文件太麻烦 → 选定方向「多开工作区，类似 VS Code」。

### 交付内容

- **store**：`workspaces: string[]` 取代单值 `workspace`（首启幂等迁移，旧键
  删除）；`recentWorkspaces`（上限 8，内存镜像同 recent 模式）供空态快速重开
- **新 lib/workspaces.ts**：samePathFold / isUnderRoot / rootOf / dedupeRoots
  / normalizeStoredWorkspaces 全纯函数（大小写折叠 + 分隔符边界）——
  FileTree 原有 isUnderPath/samePath 提取到此消重
- **FileTree 多根**：每根一个可折叠分区（chevron + 根名 + hover ×移除）；
  childrenMap/expanded 本就按绝对路径键控，跨根天然唯一 → prune 改
  underAnyRoot 即可，**FileNode 零改动**。关键 deps：`roots.join("\n")`
  而非数组身份。折叠只藏行不丢状态（再展开零 IO）
- **App**：废除「打开外部文件劫持工作区」（旧行为静默换树丢展开状态）；
  新增 add/replace/remove 根操作（replace 在 ≥2 根时确认；remove 无确认
  ——磁盘不动）；侧栏头 ＋添加 / ⤢替换 双按钮；空态列最近工作区
- **搜索**：searchWorkspaces(roots) 逐根收集、maxFiles 预算全局共享；
  WorkspaceSearch 的 lastSearch key 加 scopeKey（根列表+排除项全量
  join）——修掉「切工作区后同 query 不重扫」的旧隐患
- 菜单：文件 →「添加文件夹到工作区…」（MenuBar.tsx + lib.rs menu_ids
  ADD_FOLDER，macOS 原生菜单同构）
- SettingsModal 的 workspace prop 传 roots[0]（排除项相对路径显示基准）

### 教训

- **后台构建与后续编辑竞态**：tauri build 后台跑时又 Edit 了源码，vite
  产物是否含该改动无法确证（minified 后 grep 不可靠）→ 重跑一次 build
  收尾（cargo 增量只花 1 分钟）。今后：构建启动后不再改源码，或收尾必跑
  一次最终构建
- 编辑大块代码时 old_string 圈太大误删了仍在用的 sameEntries（靠后续读
  回补）——大编辑后立即 grep 关键符号核对

## 追记：日志分析定罪 MD-6004，修复文件监听自始失效

用户反馈「体验稳定但时有日志弹窗」→ 分析 `%APPDATA%\com.mditor.app\logs\`
（dev-anomalies 69 条：MD-1002×50 / MD-6004×8 / MD-1011×6 / MD-1001×4 /
MD-1003×2；弹窗全是 devMode 警告卡，error 级原生弹窗从未触发）。

- **定罪链（MD-6004「Command watch not found」）**：useFileWatcher 用
  plugin-fs `watch()`，但 Cargo.toml `tauri-plugin-fs = "2"` 未开
  `features=["watch"]` → Rust 从未注册 watch 命令；Cargo.lock 证实无
  notify。capabilities 的 fs:allow-watch 早就放行——**只差 cargo 特性**。
  该功能在所有历史构建中静默失效；v4.3.0 sysDebug 埋点（useFileWatcher
  catch）让它现形为告警卡。08-25 10:28-10:46 集中弹 8 条 = 那天首个
  「开着 devMode + 打开文件」的会话
- **修复**：Cargo.toml 一行 → `{ version = "2", features = ["watch"] }`，
  重编译后 watch:attach 出现、file:watch-fail 归零；NSIS 重装更新已装副本
- 其余异常定性：MD-1002/1001/1011/1003 全是大文档（74k 字符）载入/切标签
  /大纲跳转时的检测噪音，08-23（v4.2 时代）占大头，v4.3.0 resize 归因后
  基本归零——与「无 bug 体感」一致。内存健康（堆 25-34MB，08-14 起无 heal）
- **方法论教训**：日志 env.ver 读的是**打包时刻的 package.json**
  （devContext.ts `pkg.version`）→ 所有会话自报 4.3.0，11:27 的 v4.4.0
  构建从未被运行过；uptimeMs 心跳字段可还原真实会话边界（所谓"晚间会话"
  其实是 10:28 起跑全天的那一个，20:28 只是 2MB 轮转点）
- **构建坑 ×2（本次修复过程实录）**：
  1. cargo 拉新依赖报 `via 127.0.0.1 连接失败`——系统代理残留（ProxyEnable=0
     但 ProxyServer=127.0.0.1:7890，Clash 未运行，libcurl 仍拾取）。机器
     直连 crates.io 正常，`no_proxy='*' cargo build` 即绕过；别改用户代理配置
  2. **裸 `cargo build --release` 产物不可用**：窗口显示「127.0.0.1 拒绝连接」
     ——没经过 tauri CLI，二进制连的是 devUrl 而非内嵌 dist。必须
     `npm run tauri build`（内存 33MB、日志零写入 = 前端没跑，一眼识别）
- 小不一致待办：SettingsModal 内存阈值提示文案写默认 1200，实际
  DEFAULT_SETTINGS 是 2500（types.ts）；本次未动

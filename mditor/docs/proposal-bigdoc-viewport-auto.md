# 提案：大文档（≥1MB / ≥8000 顶层块）自动开启 bigDocViewport

> 状态：**待拍板**（任务书红线 8：默认设置/产品决策类改动不合入，单独成文）。
> 数据来源：`docs/large-doc-perf-report.md`（第三轮，2026-09-24）。

## 现状

`bigDocPerformance` / `bigDocViewport` 默认均为 false（defaults.ts）。1MB 级文档
默认走「全量急切渲染」路径。

## 数据（1MB 压测副本，11629 顶层块，行内公式 ≈1.58 万）

| 指标 | 默认档 | 视口档（bigDocViewport） |
|---|---|---|
| 打开（3 轮中位） | 12479ms | **5466ms** |
| 滚动 p50 / p95（scroll-abab 终测） | 6.1 / 251-279ms | **53.5 / 82ms** |
| 滚动长任务 max | 485-1206ms | 525-652ms（修复后 p95 仅 82ms） |
| 点公式事件 p95 | 728ms | **88ms** |
| 拖选事件 p95 | 648ms | **136ms** |

视口档在打开、滚动、选中三条链路全面占优；默认档唯一优势是滚动中公式即时可见
（视口档滚动静止 ~400ms 后渲染为 KaTeX 真身，滚动中显示源码占位）。

## 提案内容

文档体量 ≥1MB（或顶层块 ≥8000）时，创建实例默认开启 bigDocViewport（用户显式
关闭过则尊重用户选择）。实施点：useMilkdown 建实例时 isBigDocCv 的设置读值处
加体量旁路；设置面板文案注明「大文档已自动开启」。

## 风险与回退

- 行为变化仅限超大文档；设置项仍可手动关闭（关闭后回到急切渲染，滚动回归平滑）。
- 预热在重文档上 >45s，期间滚动已让路（R2b），打开余波由 idle 承载。
- 回退：删除体量旁路一行即恢复现状。

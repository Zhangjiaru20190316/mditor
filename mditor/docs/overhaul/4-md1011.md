### 2.3 机制（两级替换，计数 = 2H+1）

整篇应用文档（flush 的 `EditorState.create`+`updateState`，或事务式 `tr.replace(0, size)`）时，解析产物的 heading `id` attr 与在编辑器里已被 **sync-heading-id 插件**（`@milkdown/preset-commonmark`，按 `headingIdGenerator` 生成 + `-#N` 去重）盖章的 id 不一致：

1. 解析器产出的 heading id 为空 → prosemirror-view 子节点匹配按 `node.eq`（含 attrs）判死 → **每个标题块整棵 DOM 重建（第 1 次）**；
2. 文档落地后插件的 `view.update` 发现 id 缺失，dispatch `setNodeMarkup` 盖章 → **同一批标题再次整块重建（第 2 次）**；+1 来自 Crepe trailing 插件的文末空段交换。

段落/列表/代码块因结构 eq 匹配保活——**被整批替换的只有标题**（数学习题/训练手册类文档标题密集，H 可达 52~113，单次事务替换 79~227 个顶层块）。removed 侧采样全是空串的谜底：`recreateWrapper` 把子树 DOM 移植进新节点后再移除旧壳，旧元素 `textContent` 为空。

**编辑期变体**：文档存在大量同名标题（「思路分析」「详细解答」）时，编辑/插入任一标题会使后续同名标题的 `-#N` 编号整体位移 → 插件一次 `setNodeMarkup` 事务批量重建（dev 版 -226 簇）。此变体在标题文本真实变化时无法避免（id 语义如此），频率远低于整篇重载路径。

### 2.4 9/1 tb-win-btn 簇的触发入口

动作环仅有两次窗口按钮点击、无打字记录（普通打字每 2s 合并记一条「typing」，全程零条）而文档持续增长 → 内容来自程序化整篇写回（AI 辅助写作会话）。窗口按钮本身无文档副作用（`TitleBar.tsx` 仅 minimize/toggleMaximize/close）——它只是动作环里「最后一次非打字交互」的残留。**入口无法从日志唯一指认（候选：AI 全文写回 `aiWriteDoc`/`setValue`、批注回退、外部同步重载），但所有入口共用同一落地机制（§2.2 的两种整篇应用形态），根修对全部入口生效**——实机验证（§4.1）按「打开-切换-重载」最强路径覆盖。

## 3. 修复

### 3.1 根因层（A）：heading id 预盖章 —— `src/lib/headingStamp.ts`（新增）

整篇应用前，按 sync-heading-id 的**同一算法**（生成器 slice 动态读取 + 文档序 + `-#N` 去重 + 跳过空文本标题）把 id 预先盖进解析产物：

- 内容未变的重载（watcher 回声 / 标签切回 / sv 切换 / 程序化整篇写回）→ id 全同 → `node.eq` 成立 → **零 DOM 替换**；插件随后核对全部命中，不再 dispatch 盖章事务；
- 内容真变（换文件 / AI 全文改写）→ 仅文本实际变化的标题被替换（正确且最小）；
- 算法与插件逐字对齐是硬约束（否则预盖的 id 不符插件期望，替换减半不归零）——`headingStamp.test.ts` 6 例锚定；任何失败静默回退未盖章文档（行为同旧版）。

接入点（全部整篇应用路径）：

| 路径 | 改动 |
| --- | --- |
| `parsePipeline.applyParsedDoc`（flush：文件打开/缓存命中/seed/sv 切回） | 装入前 `stampHeadingIdsFromCtx` |
| `parsePipeline.replaceAllStampedDoc`（新增，事务式整篇替换的盖章版） | 解析→盖章→`tr.replace` |
| `useMilkdown.setValue`（clearStack≠true，程序化整篇重写） | 改走 `replaceAllStampedDoc` |
| `useMilkdown.insertFootnote` 回退 | 同上 |
| `useMilkdown.aiWriteDoc`（AI 全文改写） | 解析后盖章再组 Slice |

### 3.2 缓解层（B）/ 兜底层（C）：不需要

根修后仅存的替换是「标题文本真实变化」（正当代价）与「同名标题编号位移」（低频、id 语义固有）。remembered-size 保存/滚动锚定补偿无新增场景。

### 3.3 顺手修复：`rmSamples`/`addSamples` 空串 —— `scrollDebug.ts`

`pmSampleLabel`（纯函数，node 可测）：块内文本（32 字）为空时回落结构指纹 `<tag.cls>子tag ×N>`——空壳（移植后旧元素）、纯容器（UL）、widget div 从此可辨识；MD-1011 日志条目自带「替换了什么」的线索。附带修复 `devContext.test.ts` 版本号正则不容 prerelease 后缀（beta 版本号下预存失败）。

# 项目全面优化提示词（性能 / 安全 / Bug / 工程规范）

> **使用方式**：将本提示词完整粘贴给 AI 编码代理作为任务指令。默认目标项目为 `mditor/`（Tauri 2 桌面应用）；如需用于其他项目，仅需替换「二、项目背景」一节。

## 一、角色定义

你是一名资深全栈工程师（前端 React/TypeScript + Rust + 桌面安全方向），受命对本项目执行一次系统性的全面治理，覆盖四个目标：**性能优化、安全漏洞排查、Bug 修复、工程规范化**。你以证据驱动决策，反对凭感觉改代码；每一项改动都要能回答"为什么改、改了之后如何证明有效、如何回滚"。

## 二、项目背景（先读再动手）

- **产品**：mditor — 本地优先的 Markdown 编辑器（类 Typora），版本 4.6.1。
- **前端**：React 18 + TypeScript + Milkdown（ProseMirror）+ CodeMirror 6 + Vite 5；unist/remark/rehype 管线负责 Markdown 渲染与导出；KaTeX 数学公式、highlight.js 代码高亮。
- **后端**：Tauri 2，Rust 侧源码在 `src-tauri/src/`（`commands.rs`、`ai.rs`、`lib.rs`），插件涉及 fs / dialog / shell / process / store。
- **既有基建**：`npm run build`（含 tsc --noEmit）、`npm run test`（Vitest）、`npm run lint`（ESLint）；`perf/` 目录下有性能基准与归因工具；`patches/` 有 patch-package 补丁；`CHANGELOG.md` 维护发布历史；仓库约定见 `AGENTS.md`。
- **历史**：项目已经历两轮性能治理（选中与编辑链路卡顿），沉淀了「假阳性归因」「基准漂移纪律」等经验——延续这些纪律，不要推倒重来。

动手前必须实际阅读：`AGENTS.md`、`CHANGELOG.md` 近几个版本、`src/` 与 `src-tauri/src/` 的目录结构、`perf/` 现有基准脚本。

## 三、总纪律（所有阶段通用，优先级最高）

1. **先基线，后动手**：任何优化/修复前先记录当前状态（构建、测试、lint、性能数据），没有基线的改动一律不做。
2. **小步提交，独立可回滚**：每项改动一个 conventional commit，禁止大杂烩式提交。
3. **证据链完整**：性能问题必须有 profile 数据支撑归因；Bug 必须先复现再修复；警惕测量假阳性（devtools 自身开销、热更新干扰、后台任务噪声）。
4. **行为兼容**：用户数据格式、设置项、快捷键、文件兼容性不得破坏；涉及迁移必须先提案确认。
5. **依赖克制**：不引入新依赖，除非收益明确且现有能力无法实现；升级依赖前评估破坏面。
6. **正确性优先于数字**：禁止用禁用功能、放宽校验的方式换取性能或测试通过。
7. **阶段推进**：按 0 → 1 → 2 → 3 → 4 顺序执行；每阶段结束输出报告，等待确认后进入下一阶段（若我明确说"连续执行"则自动推进）。

## 四、阶段 0：环境与基线（必须最先完成）

1. 确认可构建、可测试、可检查，并记录初始状态：
   - `npm run build`（tsc --noEmit + vite build）
   - `npm run test`（记录通过/失败/跳过数）
   - `npm run lint`（记录 error/warning 数）
   - Rust 侧：`cargo check` / `cargo clippy`（在 `src-tauri/`）
2. 运行 `perf/` 下既有基准，采集性能基线；注意基准漂移——固定测试环境（同一文档样本、关闭无关进程）、多次取样取中位数。
3. 产出《基线报告》：版本号、四项检查结果、性能数据表、环境说明。

## 五、阶段 1：性能优化

### 5.1 摸底（覆盖全部关键路径）

| 路径 | 关注点 |
|---|---|
| 冷启动 | 主进程/WebView 初始化、首帧时间 |
| 大文档打开 | ≥1MB 或 ≥5 万字文档的解析、首次渲染 |
| 打字输入 | 按键到渲染延迟，输入法组合输入 |
| 选区/拖选 | 选区变化引起的重渲染范围 |
| 滚动 | 视口渲染有效性、滚动帧率 |
| 导出 | HTML/DOCX 导出的同步阻塞 |
| 搜索替换 | 全文扫描的阻塞与高亮渲染 |
| 文件保存 | 写盘时机、防抖、大文件 IO |

### 5.2 归因要求

- 每个瓶颈必须给出完整证据链：**现象 → 测量数据 → 根因分类**（CPU / 布局抖动 / 过度渲染 / IO / GC / 锁竞争）。
- 根因定位到具体文件与函数，附 profile 截图或数据表。
- 先排除假阳性：确认不是测量工具本身、React StrictMode 双渲染、dev 模式差异造成的干扰，必要时用 release 构建复测。

### 5.3 优化与验证

- 只修有数据支撑的瓶颈，按「收益/风险比」排序执行。
- 结合本项目历史，优先考虑的杠杆：视口渲染与 `content-visibility`、React 重渲染收敛（memo/依赖收敛/状态下沉）、防抖节流、重活下放 Web Worker（`src/workers/`）、Rust 命令异步化避免阻塞主线程。
- 每项优化：单独提交，提交说明中写明**优化前后的基准对比数据**。
- 每项优化后回归：核心功能手测清单 + 全量自动化测试。

### 5.4 产出

《性能优化报告》：瓶颈清单（含证据）→ 已修复项（前后数据）→ 未修复项（原因与建议）→ 回归结论。

## 六、阶段 2：安全漏洞排查

### 6.1 前端 / WebView 侧

- **XSS**：重点审查 `rehype-raw` 与 `rehype-sanitize` 的配置顺序和白名单完整性；逐一检查粘贴、导出 HTML、KaTeX 公式渲染、代码高亮、`dangerouslySetInnerHTML`（如有）等入口。
- **供应链**：`npm audit` 全量审计；审查 `patches/` 下每个 patch-package 补丁的必要性与内容；Rust 侧 `cargo audit`（如可用）。

### 6.2 Tauri 能力面（桌面应用核心攻击面）

- **capabilities 最小化**：逐条审查 fs / shell / dialog / process / store 各插件的 scope，收紧到实际需要的最小集合。
- **命令逐个审计**：对每个 `#[tauri::command]` 检查——路径穿越（`../`、绝对路径、符号链接逃逸）、命令注入（参数拼接到 shell）、任意文件读写、TOCTOU。
- **配置**：CSP 是否收紧、release 与 dev 配置差异、webview 选项（devtools 是否泄漏到 release）。

### 6.3 Rust 侧

- `ai.rs`：API key 的存储方式、是否会在日志/错误信息中泄漏；对外请求是否存在 SSRF 面。
- 全量 `unwrap()`/`expect()`/`panic!` 审查——凡涉及用户输入路径的必须改为优雅错误处理。
- 错误信息不得泄漏内部路径、密钥等敏感内容。

### 6.4 数据与隐私

- 设置、草稿、会话等本地数据的存储位置与文件权限；日志脱敏。

### 6.5 产出

- 《安全审计报告》：每项含 **风险等级（P0 严重 / P1 高 / P2 中 / P3 低）+ 代码位置 + 利用路径 + 修复建议 + 处置状态**。
- P0/P1 直接修复并附验证方式；P2/P3 列清单待我决策。

## 七、阶段 3：Bug 修复

**来源**：阶段 0-2 中暴露的失败测试与隐患、已知 issue、CHANGELOG 中标记的遗留问题、排查过程中发现的异常行为。

**每个 Bug 强制流程**：

1. **复现**：写出最小复现步骤；无法稳定复现的记录触发条件，不许盲目修改。
2. **根因**：定位到根本原因，禁止只治症状（例如只是把报错吞掉）。
3. **修复**：最小改动修复根因。
4. **回归测试**：能自动化的必须新增 Vitest 用例固化，防止复发。
5. **登记**：写入 CHANGELOG（fix 类型）。

**产出**：《Bug 清单》表格——编号 / 复现步骤 / 根因 / 修复方式 / 回归测试。

## 八、阶段 4：工程规范化

- **TypeScript**：消除 `any` 与隐式类型逃逸；逐步收紧 `tsconfig`（strict 系列开关全开），收紧过程若报错过多则分批推进并记录计划。
- **ESLint**：清零 error 与 warning；审查规则集是否有缺口（如 react-hooks 完整性）。
- **Rust**：`cargo clippy --deny warnings` 通过；`cargo fmt` 统一格式。
- **测试**：核心路径（Markdown 解析、文件读写、导出管线、设置存取）补齐用例；测试与源码同步演进，删除针对已删功能的陈旧测试。
- **提交规范**：conventional commits（`feat` / `fix` / `perf` / `docs` / `chore` / `refactor` / `test`），保持与仓库历史一致。
- **文档**：README 补充架构与目录说明；`AGENTS.md` 中新增的约定同步更新；CHANGELOG 维护纪律固化。
- **仓库卫生**：日志文件、构建产物不入库（完善 `.gitignore`）；`patches/` 补丁补注释说明用途。
- **CI（可选，先提案）**：最小流水线 = lint + typecheck + test + build。

## 九、验收标准（Definition of Done）

1. `npm run build` / `npm run test` / `npm run lint` 全绿；`cargo clippy` 无警告。
2. 性能：基线报告中的每个已处置瓶颈均有前后对比数据，且无其他指标回退。
3. 安全：不存在未处置的 P0/P1。
4. 每个 Bug 修复都有对应回归测试。
5. 全部工作以小步 conventional commits 提交，CHANGELOG 已更新。
6. 四份报告齐备：《基线报告》《性能优化报告》《安全审计报告》《Bug 清单》。

## 十、红线（违反即停）

- 不删除、不迁移用户数据；不做文件格式变更。
- 不替换框架、不引入重量级依赖。
- 不以牺牲正确性或安全性换取性能数字。
- 不在未告知的情况下修改构建脚本、CI、发布流程。

# v3.9 系统性优化：诊断报告与改动设计

> 范围：批注交互（1–2）、AI 面板（3–4）、滚动/渲染性能（5–8）、后台开销与系统级影响（9–11）、AI token 降本（12）。
> 方法说明：本轮诊断基于共享机制的静态调用链分析（问题清单中的「已核实线索」逐条在源码定位确认）+ 149 例单元测试回归。Performance 面板的动态录制（帧级火焰图、重绘计数）需要在真机 WebView2 上操作 DevTools，本报告在相应条目标注了建议的录制步骤与预期观测值，供发布前人工复核；所有改动的机制性根因均有代码级实锤。

## 第一部分：批注交互

### 问题 1：代码块 AI 批注闪烁、点不开

**复现路径**：AI 回答 →「批注」→ 流式精炼开始 → 观察代码块区域。

**根因确认（代码级）**：

1. **闪烁**：`App.onAnnotateReply` 的每个流式帧（rAF 节流后仍 ~60fps）走
   `Editor.updateAnnotation` → `updateAnnotationInMd`（整篇字符串重写）→ `setValue` →
   `replaceAll(md, false)` → Milkdown 整篇重新解析 → **全部代码块的 CodeMirror 子编辑器连根重建**。
   即使批注只改了文档尾部一个隐藏定义行，ProseMirror 也收到一个覆盖全文档的替换步。
2. **点不开**：
   - 弹层定位 `useLayoutEffect` 依赖 `[activeId, active?.content, orphanId]` —— 流式期间
     `active?.content` 每 ~150ms（防抖列表刷新）变化一次，每次触发 `placeCard` 的
     全文档 `querySelectorAll` + 每徽章 `getBoundingClientRect` 批量强制布局，
     与文档重写互相打架（定位追赶重排后的 DOM）；
   - 代码行高亮类直接画在 `.cm-line` DOM 上，任何触及该代码块的事务重绘 node view 即被抹掉。
3. **关闭误杀**：见问题 2。

**改动设计**：

| 改动 | 动因 | 影响面 | 回滚点 |
|---|---|---|---|
| `MilkdownFacade.updateAnnotationBody(id, content, meta)`：定位 `footnote_definition` 节点（`doc.descendants`），用 `buildDefinition` 源码解析出新节点后 `tr.replaceWith` 定点替换 | 只重渲染变化区间，代码块 DOM 不动 | `Editor.updateAnnotation`（唯一调用方）；失败/sv 自动回退旧整篇路径 | 删除该方法 + Editor 调用点即回旧行为 |
| `Editor.updateAnnotation` 首帧缓存 codeLine 元数据（`annoMetaCacheRef`） | 整篇解析 O(doc) 只付一次 | 无外部契约变化 | 同上 |
| 弹层定位去 `active?.content` 依赖，改 `[activeId, layoutEpoch, orphanId]`；`commitEdit` 显式 bump `layoutEpoch` 重测 | 流式内容变化不触发定位（定义块是 CSS 隐藏的，徽章不动） | 编辑保存后的重定位由显式 epoch 承接 | 恢复依赖数组旧值 |
| `setActiveCodeHighlight` / `restoreCodeLineHighlights`（`lib/codeAnno.ts`）：记录活动高亮锚点，stamp 管线在每次 DOM 变化后补画（不滚动） | 高亮在 node view 重绘后存活 | `useAnnotationMarkers` 合并 pass 多调一个幂等函数 | 移除 restore 调用 |

**契约保持**：一步撤销不变 —— 定点事务照常进历史，相邻帧由 prosemirror-history 的
newGroupDelay 合并；收尾仍走 `aiWriteFinalize(baseline, next)`（baseline 无历史还原 +
单事务写入），按一次 Ctrl+Z 回到点「批注」之前。

**建议 Performance 复核**：录制流式精炼 10s。预期：改动前每帧一次全文档 reparse +
若干 CodeMirror 重建（长任务 >30ms 连串）；改动后仅定义节点区间重渲染，帧耗时 <5ms。

### 问题 2：普通批注徽章二次点击

**根因确认**：v3.6.6 已修「点击时刻现场解析兜底」，但**关闭 effect** 仍是
「props 列表 miss → 用 rAF 镜像 `markdownRef.current` 解析 → miss 即 `close()`」。
镜像滞后一帧时（插入后立刻点击的典型时序），刚打开的弹层立即被关闭——表现为第一次点击无反应。

**改动设计**：`AnnotationPopover` 的 prop 从 `markdown`（rAF 镜像）改为
`getMarkdown()`（编辑器实时序列化，同步新鲜）；关闭判定改为
「props miss + 现场同步解析 miss + **60ms 重试后仍 miss**」三级确认后才关闭。
孤儿判定只在确认缺失后介入（原有行为）。

**回归场景（全部应一次打开）**：批注刚创建后立即点、文件切换后立即点、流式精炼中点开、
相邻徽章挨着点、普通脚注旁点。

## 第二部分：AI 面板

### 问题 3：追问不能选择回答中的具体内容（新功能）

**实现**：

- 已完成回答的正文区（`ai-msg-body`）监听 `selectionchange`；选区两端均落在该正文内
  且非折叠时，选区下缘浮现「追问这段」按钮（行内绝对定位，钳位行宽内）。
- 点击后：`followUpQuote` 存入面板状态 + 打开行内追问框（引用条展示在输入框上方）；
  提交时用户消息为 `问题\n\n<quote>\n片段\n</quote>`，Msg 记录 `quote` 供线程渲染。
- 追问仍挂 `parentId` 线程链；历史沿链回溯时早期消息里的 `<quote>` 块自然携带。
- 草稿与引用由 AiPanel 层持有（虚拟列表回收行不丢、不串行）。

**边界用例**：跨行划选（取纯文本，空白归一）；选中代码块（纯文本快照）；
流式未完成不可追问（`selectable = !streaming && hasContent`）；Esc 取消选区入口；
Enter 发送 / Shift+Enter 换行；划选不破坏操作按钮（入口按钮 mousedown preventDefault）；
全文与选区两种上下文模式均可用（选区追问不带 note，见问题 12）。

### 问题 4：回答/批注内容渲染闪现

**根因确认**：`MarkdownText` 用 `useEffect` 异步 `renderMarkdown`，未命中缓存时
先提交空 div、Promise 落地后才写 innerHTML —— 中间必有一帧空白（effect 在 paint 后）。
缓存命中的重挂载也经 `.then` 微任务，存在一帧间隙。流式纯文本与渲染态排版不同
（后者显式 13px/1.65，前者继承气泡字号）加剧跳变感。

**改动设计**：渲染移入 `useLayoutEffect` + 新增 `peekRenderedHtml` 同步探针：
命中 → 同帧直出最终 HTML；未命中 → 同步写入排版一致的纯文本占位
（`.md-ph`，13px/1.65/pre-wrap），管线完成后替换。`.ai-streaming` 排版对齐。
LRU（64 条 / 8MiB）不回归；不阻塞主线程（管线仍异步）。

## 第三部分：滚动与渲染性能

### 问题 5：滚动偶发卡顿

**逐条判定**（对照线索清单）：

| 线索 | 判定 | 处置 |
|---|---|---|
| 无 scroll 监听器 | 属实，排除 | — |
| 图片 lazy 无宽高预留 | **确认**：加载完成高度突变 → 整篇回流 | 会话级自然尺寸缓存（捕获阶段 load 委托）+ `aspect-ratio` 预盖；首次浏览仍会移动（解码前无尺寸信息，物理极限） |
| content-visibility 物化 | 属实但为设计代价（保交互零回归），滚动条抖动已由 contain-intrinsic-size 缓解 | 不动 |
| 键入停顿后 3–4 次全树查询 | **确认且翻倍**：stamp 有两条并行通道（markdownUpdated 双 rAF + MutationObserver 60ms 防抖） | 合并为 MO 单通道（问题 7） |
| 内存守护撞滚动帧 | **确认** | 活动门控（问题 10） |

### 问题 6：页面偶发抖动

| 线索 | 判定 | 处置 |
|---|---|---|
| 图片高度突变 | 最强候选，同上 | aspect-ratio 预留 |
| sv 平滑标志只盖同步阶段 | **代码实锤**：`smoothJump.active` 在 dispatch 后同步复位 | 覆盖动画全程（scrollend/1.2s 兜底） |
| 富文本 centerCaret 与滚轮互掐 | **确认**：selectionchange → 量 rect + 改 scrollTop，与惯性滚动方向相反时 16px 死区无济于事 | 滚轮后 350ms 让位；大纲平滑跳转支持滚轮打断 |
| jumpToHeading 残余竞争 | scrollend/超时已兜底；残余是打断后光标跟随恢复慢 | wheel 一次性解除 smoothJump |

### 问题 7：编辑路径全树遍历合并降频

**改动**：`useAnnotationMarkers` 的 MutationObserver 成为唯一驱动
（60ms 防抖 + rAF），一次 pass 完成：批注徽章 stamp ＋ 图片 lazy/aspect stamp ＋
代码行高亮补画；删除 `useMilkdown.markdownUpdated` 里的重复双 rAF stamp。
早退缓存从「无注解」扩展到「无注解且无图片」（mutation 记录含 IMG 判定）。
标题走查维持既有「微任务合并 + doc 引用去重 + 签名去重」（PM 树遍历、零 DOM 查询）。
批注侧栏摘要改 `getAnchorSnippets` 单次扫描（O(doc) 替代 O(批注数×doc)）。

**量化（分析值）**：500KB 文档 + 50 批注，每次键入停顿：
旧 = 2 通道 × 2 次全树 querySelectorAll + 50 次全文正则（~25MB 扫描）；
新 = 1 通道 × 2 次全树 querySelectorAll + 1 次全文正则。
无注解无图片文档：旧每停顿仍有 2×2 次查询，新为 0（记录级早退）。

### 问题 8：弹层定位与打开开销

打开时一次性测量（50 徽章 ≈ 一次批量布局读取，~1–2ms，可接受）；流式期间零重测
（问题 1 的每帧重算已消除）；滚动帧仅测锚点一个元素 + 算术平移；resize/保存/切换重测。
`resolveCodeLines` 的全文扫描保留在打开路径（一次性、毫秒级）。

## 第四部分：后台开销与系统级影响

### 问题 9：常驻动画与全屏遮罩

- `fab-pulse`：box-shadow → transform+opacity（合成器属性，空闲期零 repaint）；
  窗口隐藏暂停（`.app-idle`，visibilitychange 维护）；reduced-motion 关闭。
- `md-heavy-veil`：1.4s infinite + 常驻 will-change → 0.3s 一次性淡入（遮罩静态在场）。

### 问题 10：内存守护与编辑器重建

**主动重建触发点清单**：

| 触发点 | 条件 | 频率上限 | 用户影响 | v3.9 变化 |
|---|---|---|---|---|
| 守护软重建 | 堆 > 阈值 + 过 60s 冷却 + 未退避 | 60s | 光标/滚动重置 | 活跃期推迟 + 滚动/光标恢复 |
| 守护升级 reload | 软重建 8s 后仍超，或临界（>90% 上限） | 3min | 整页刷新（会话快照恢复） | 非临界时活跃期推迟（重试阶梯也推迟） |
| idle 历史回收 | 大文档 + ≥1000 次编辑 + 3min 无编辑 + 堆 ≥80% 阈值 | 一次/千次编辑 | 同软重建 | 加 2min 活跃门控（阅读/滚动不打断） |
| big-doc 档位翻转 | 整篇载入跨越 3000 行/500KB | 随文件切换 | 重建（内容自然切换中） | 不变（语义上属于载入） |

巡检周期（10s）、阈值（2500MB）、临界比（0.9）均未削弱。

### 问题 11：定时器梳理

全部站点核查结论（均有卸载/关闭清理，无泄漏）：
ThinkingDots 200ms（仅流式占位期间挂载）、内存守护 10s（enabled 门控 + 活动推迟）、
dev 堆探针 30s（IS_DEV）、状态栏时钟 2s、自动保存间隔（可配）、sv 通知防抖 200ms、
标注 stamp 防抖 60ms、搜索/文件树/工具栏的防抖轮询、解析 worker 超时（逐请求清理）、
splash 一次性淡出（boot 一次）。filePrefetch 空闲预解析已由内存压力模式门控。

## 第五部分：AI token 降本（问题 12）

按计划全部落地：`truncateNoteForContext`（full/standard/large/smart，smart 为本地
字符级共现打分 + 标题恒保留 + 头尾段）、`estimateTokens`（CJK/1.5 + ASCII/4）、
`buildHistoryWithBudget`（尾部保留 + 孤儿回答修剪 + system 恒留）、
`buildAnnotationMessages` 输入截断（默认 4000）、设置项三个
（aiContextStrategy / aiHistoryBudgetTokens / aiAnnotateMaxChars，老配置经
DEFAULT_SETTINGS 合并自动补齐；aiMaxTokens 0/缺失 → 4096）、面板用量统计行。
追问降本：full 带截断 note，selection 不带 note。

**预期收益**（与计划一致）：长文档多轮聊天输入省 70–90%；长对话省 50%+；批注精炼省 60%+。

## 回滚点总览

每项改动独立可回退：定点批注更新（facade 方法 + Editor 调用）、弹层判定（prop 换回 markdown）、
弹层几何缓存（恢复旧 deps + placeCard 签名）、stamp 合并（恢复 markdownUpdated 双 rAF）、
图片 aspect（移除 stamp 三行）、sv 标志（恢复同步复位）、滚轮让位（删 onWheel）、
MarkdownText（恢复 useEffect 版）、CSS 动画（恢复旧 keyframes）、守护门控（删两处 isUserActive）、
token 层（策略默认 standard→full 即恢复旧行为；预算调极大等效关闭）。

## ② 归因结论（详细版 `perf/results/r8-phase4-attribution.md`）

### 掉帧 vs 跳位判别
三哨兵残差口径（Δrect.top + ΔscrollTop，>4px 判真跳位）：**全部 20+ 个 run 的 scrollPhase 窗残差位移 = 0**。症状 U 全部为掉帧（帧间隔拉长），无内容跳位成分。U-f 排除，R7 漂移残余维持留档。

### 候选定罪/排除表

| 候选 | 结论 | 关键证据 |
|---|---|---|
| U-e 版本差 | **排除** | 用户构建=10-03 对齐构建（含 R4~R7）=HEAD 同源；dev 复测仍有形态 |

| U-a 停滚补绘墙 | **部分成立（降级非靶）** | quietPhase 52-60 jank 帧/10s、task 96% 满载（script 5s）；但残差位移=0（内容稳定），用户停滚阅读感知弱 |

| 方向不对称（原立论） | **证伪——位置混杂伪象** | exp1 深位对照：同位置上下完全对称（1MB 1.02/0.97；密度档 1.05） |

### 主靶机制链（冷区首渲布局墙）
1. 预热（cvMemory）完成 cv 变现+缓存预热，**不渲染行内公式** → 全文档 25,256/25,270 unready（打开时视口带内除外）。
2. **预热完成区**（头部 0-5000px，打开+预热期补绘完成）滚动：带内条目 ready → 队列 0（实测恒 0）→ 帧间隔 = 布局墙底（p95 104~119ms）。
3. **冷区**（文档中部）滚动（**方向无关**）：IO 带内 unready 条目持续入队 → 直绘受限（SCROLL_HIT_PAINT_CAP）+ 冷条目留队 → **队列膨胀至 3,000+**（实测 max 3,310）→ 视口内条目 5ms 预算内首渲（KaTeX render 1-2ms/条，**布局成本不计入预算时钟**）→ 每条首渲改行框/块高 → **全树强制 layout ~67ms/帧**（exp2 metrics：up 段 LayoutDuration +1.078s/16 帧）→ 帧间隔 150~400ms 均匀分布（与"每帧首渲"模型一致，掉帧窗与 prewarm/写入零对齐）。
4. 每像素任务消耗：up 段 0.51 ms/px vs down-leg 0.24 ms/px（2.1×）——冷区条目密度差异所致，非方向调度差异。

### 口径修正声明（红线 11 不违反：不改指标定义，修正对照臂位置）
任务书 U1 原口径"同强度下滚为对照臂"以头部下滚为对照（down 臂 0→5000px）。阶段四 exp1 证明**文档位置是比方向强一个量级的变量**（头部 p95 104 vs 中部 195~353）：
- 原口径对称比：1MB p95 比 1.67~5.5、密度档慢滚 1.70~1.80——**伪不对称**（up 臂驱动在中部、down 臂在头部）。
- 修正口径（`--start-depth 0.6` 深位下滚对照）：1MB up-slow 199.1 vs deep-down-slow 195.6（**比 1.02**）、jank32 比 0.97；密度档 up-slow 11.7 vs deep-down-slow 11.1（**比 1.05**）。
- **上下滚调度本身对称**（R4-①/R6 Fix-B 的方向带设计未产生帧稳定性不对称）；两档修正口径均 ≤1.25 达标。双口径数据全部留档供审计。

## ⑤ 遗留与放弃

### P3 拍板材料（本轮核心产出之一）
- **机制**：预热批（cvMemory chunk）测量时从 katexCache 取渲染态 HTML 测高，使泵学得的 hasReservedBox 覆盖全文档 → 冷区条目滚动中走安全直绘（isCached && hasReservedBox，R6 Fix-B 条件）→ 队列不积压、首渲块高零变化 → 全树 layout 循环消失。
- **本轮新增证据**：冷区滚动队列膨胀 3,310（直绘受限+冷条目留队）、每帧 layout 67ms、禁 demote 后仍剩 ~133ms（首渲成分）。
- **预期收益**：1MB 冷区滚动 p95 199→~130（接近布局墙底 104~119）、jank32 占比 80%→~50-60%；密度档 p95 11→~7。**同步改善** U4 呈现不对称与 quietPhase 补绘墙（U-a）。
- **原型数据**：R7 锁盒原型 32/32 零差（{w,h} 记忆占位可行）。
- **成本/风险**：预热批增加 25k 公式渲染态测高（时长待原型实测）；需 §8 三规模档实测 + 1,000 次随机编辑差分 + 降级开关。**等用户拍板后另行立项**。

### 负结果留档
1. **"上滚方向调度不对称"假设证伪**——exp1 深位对照同位置上下对称（1.02~1.05）。原口径的 up/down 差全部由文档位置（预热覆盖区 vs 冷区）混杂产生。后续轮次禁用"头部 down 对照 vs 中部 up"的口径。
2. **"泵全队列活读 rect"假设证伪**——ioVisible 为 IO 回调缓存布尔（`lazyInlineMath.ts:633`），队列遍历成本微秒级，非掉帧源。
3. **预热增量批掉帧对齐证伪**——滚动中 prewarm.chunk 增量（526→551）与掉帧窗零对齐。
4. **禁 demote 不归零**——p95 133（≈布局墙底 110 + 首渲尾巴），demote 非唯一源。
5. **1MB 快滚 jank32 帧数比不稳**（16 帧级样本）——快滚 5000px 窗内仅 16~30 帧，统计效力不足；对称性判定以慢滚大样本（173~315 帧）为准。

### 放弃项（红线约束）
- "放开上滚冷算"（撤销 R6 Fix-B）：不许尝试（§3 最高危禁区）。
- DEMOTE_DELAY/SCROLL_RENDER_BUDGET_MS/SCROLL_HIT_PAINT_CAP 等常量调整：红线 1 锁死。
- 冷算条数软上限等微优化：收益仅限帧间隔极值（每帧仍 ≥1 次全树 layout），不值得为此破 §8 立项门槛。

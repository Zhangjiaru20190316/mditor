# Mditor 知识功能套件 · 功能介绍

> 适用版本：v4.7.0-beta.1 及以上。语法规范与设置的技术细节见 [research-features.md](./research-features.md)，验收样例见 [demo.md](./demo.md)。

Mditor 一直是一个「快、轻、本地」的 Markdown 编辑器。v4.7 的知识功能套件在此基础上回答一个新问题：**当你用 Markdown 做科研和学习时，编辑器还能替你多做哪些事？**

答案是五个功能：全库秒开（Ctrl+P）、双向链接、学术引用链、间隔重复闪卡、库级 AI 问答。它们共享同一个全库索引地基，全部数据留在你自己的电脑上。

---

## 这些功能为谁而生

如果你符合以下任何一条，这套功能就是为你准备的：

- **文献阅读者**：读论文做笔记，三个月后想不起「那篇讲消融实验的文章我记在哪了」；
- **论文写作者**：写综述时在 Zotero、Word、Markdown 之间反复横跳，只为插一条引用、对一个编号；
- **备考与长期学习者**：笔记记了几百篇，但从来没有一套复习机制，学过即忘；
- **AI 重度用户**：对单篇笔记问 AI 已经不够了，你想问的是「**我整个笔记库里**关于 X 都记了什么」。

---

## 五个模块总览

| 模块 | 一句话 | 默认 |
| --- | --- | --- |
| ① 全库索引 + 快速切换器 | Ctrl+P，模糊输入即达全库任意笔记 | 开 |
| ② 双向链接 + 反链 + 标签 | `[[双链]]` 把笔记织成网，反链面板让每一篇都被看见 | 开 |
| ③ 学术引用链 + LaTeX 导出 | .bib 文献库 + `[@citekey]` + 自动参考文献表 + 一键导出可编译的 .tex | 开（需配置 .bib） |
| ④ 间隔重复闪卡 | 笔记里做卡、应用内复习，SM-2 调度对抗遗忘 | 开 |
| ⑤ 库级 AI 问答（RAG） | 对整个笔记库提问，回答附可点击来源 | **关**（消耗嵌入 API） |

共同的设计底线：

1. **本地优先**——索引、闪卡进度、向量库只存在你的电脑上，无遥测、无上传；
2. **语法零迁移**——所有新语法（双链、引用、闪卡）在导出 HTML / PDF / Word / LaTeX / 复制富文本时自动降级为标准 Markdown 形态，**导出的文件离开 Mditor 依然完好可读**；
3. **不打扰**——所有后台工作（索引扫描、向量构建）分批 + 空闲调度，大文档性能模式下自动让路给正在打字的你。

## 模块 ①：全库索引 + 快速切换器

**场景**：笔记库几百篇，文件树里翻三层才找到目标。

按 **Ctrl+P**，弹出快速切换器：输入文件名或标题的任意片段（支持拼音首字母式的模糊匹配），回车即达。排序不只是「匹配度」——你最近打开过的笔记会被加权置顶，越常用的越顺手。

**背后的工程**：打开工作区时，Mditor 在后台以轻量行扫描（不解析全文语法）分批索引所有 .md 文件的标题、大纲、双链、标签、闪卡，千篇级别的库不会冻结界面；你保存一篇笔记，索引**毫秒级**增量更新这一篇，绝不全量重建。索引只存在于内存中，不落盘、不上网。

## 模块 ②：双向链接 + 反链面板 + 标签

**场景**：知识不是文件夹树，是网。你在《消融实验记录》里提到《基线模型》，希望两边都能跳过去。

- **写**：输入 `[[` 立即弹出全库补全（按文件名/标题匹配，<100ms），支持 `[[目标|显示文本]]` 别名；打完 `]]` 即时变成链接 chip。
- **跳**：点击 chip 直达目标笔记；目标重名时按路径消歧提示。
- **被看见**：侧栏「链接」页有**反向链接**面板——谁引用了当前笔记、引用处上下文是什么，一目了然；还有**全库标签**面板，行内 `#标签`（含层级标签如 `#科研/入门`）自动收集，点击即过滤出相关笔记列表。

双链语法在导出时自动降级：索引能解析的目标变成标准相对链接，解析不到的变成带样式提示的纯文本——收件人不需要装 Mditor。

## 模块 ③：学术引用链 + LaTeX 导出

这是为论文写作准备的完整闭环：

**第一步，配置文献库。** 设置 → 知识功能 → 选择 Zotero（Better BibTeX）导出的 `.bib` 文件。Mditor 内置自研 BibTeX 解析器，兼容真实导出的各种形态（`@string` 缩写、值拼接、花括号保护……），坏条目自动跳过并在界面上告警，绝不因一条坏数据中断 200 条的库。

**第二步，随手插引用。** 选中文字 → 工具栏「@」打开引用选择器，按标题 / 作者 / citekey / 年份搜索，回车即插入 `[@citekey]`。也支持手写语法：

```markdown
自动编号研究可追溯至 [@robinson2006]；
后续验证见 [@robinson2006, pp. 12-13] 与 [@zhao2019]。
```

**第三步，文末自动生成参考文献表。** 在文档末尾写一行 `# References`（或 `# 参考文献`）即可——标题下方会自动出现按样式生成的文献表（编辑器内是只读预览，导出时是正式列表）。两种样式随设置切换：

- **numeric**：行内显示 `[1]`、`[2, p. 12]`，文献表按引用出现顺序编号；
- **author-year**：行内显示 `(Smith & Lee, 2020)`，文献表按第一作者字母序（APA 简化形态）。

**第四步，图表编号。** 给图片加属性、给表格加说明行，正文用 `@fig:xxx` / `@tbl:xxx` 引用：

```markdown
![训练损失曲线](loss.png){#fig:loss}

如 @fig:loss 所示……

| 方法 | Acc |
| --- | --- |
| Ours | 87.4 |

: 主结果对比 {#tbl:main}

主结果见 @tbl:main。
```

渲染与导出中，`@fig:loss` 变成「图 1」，说明行变成斜体的「表 1：主结果对比」。

**第五步，一键导出 LaTeX。** 菜单 → 文件 → 导出 LaTeX (.tex)。转换完全在前端完成（不依赖 Pandoc、不执行任何外部命令）：公式源码天然平移、`[@key]` 变 `\cite{key}`、References 变 `thebibliography` 环境、表格变 booktabs 风格 `tabular`。产物是 ctexart 文档，扔进 Overleaf 选 XeLaTeX 直接编译——中文、公式、表格、引用全部就位。

**一致性的承诺**：编辑器 chip、AI 面板静态渲染、导出 HTML、导出 LaTeX 四处的引用编号与文献表由**同一份格式化函数**驱动，不存在「编辑器里是 [1]、导出变成 [3]」的错位。

## 模块 ④：间隔重复闪卡

**场景**：笔记记了 = 学会了？不复习的话是的。

**做卡，在笔记的上下文里**：

- 选中一段文字 → 工具栏「卡」→ 弹层里答案已预填，补一句问题即可插入；
- 或者更省事：选中文字 → AI 菜单「改写为问答卡」——AI 把这段内容改写成一对自包含的问答，**经你确认**后才插入（不满意可一键重新生成）。

卡片长这样（就是普通 Markdown，任何编辑器都能打开）：

```markdown
:::flash
最小二乘估计的闭式解是什么？
---
$\hat{\beta} = (X^\top X)^{-1} X^\top y$，要求 $X^\top X$ 可逆。
:::
```

在编辑器里它是卡片样式的块，内容照常编辑。

**复习，在应用内**：菜单 → 视图 → 复习闪卡。逐卡出题 → 空格翻面 → 四档自评（忘了 / 困难 / 良好 / 轻松，对应键盘 1-4）。调度算法是 SM-2 简化版：间隔按 0、1、3、7、14、30 天进阶，再乘以一个随你的表现微调的 ease 因子——答得好间隔拉长，忘了就打回重学。

**贴心的细节**：

- 进度存在本地 `review-state.json`，文件损坏自动重建，绝不崩；
- 源笔记改动导致卡片内容变化时，旧进度标记为「需重定位」提示你，而不是悄悄错配；
- 复习卡片上显示来源笔记，点一下跳回原文那一行；
- 到期扫描复用全库索引，保存即更新，无需手动同步。

## 模块 ⑤：库级 AI 问答（RAG）

**场景**：你的笔记库已经是一个知识体，但你只能一篇篇问 AI。

在 AI 面板打开「全库问答」，之后你的每个问题都会：**嵌入成向量 → 在全库检索最相关的 8 个片段 → 连同来源交给对话模型 → 流式回答**。回答下方列出全部来源（文件名 › 标题），**点击直达对应笔记的对应小节**——AI 说的每一句话都能溯源。

**为你的 API 账单着想的设计**：

- 默认关闭；需要显式配置独立的嵌入模型（如 `text-embedding-3-small`）；
- 首次构建前弹出成本确认，明示「将调用嵌入 API 处理 N 个文档」；
- 构建分批后台进行，**随时暂停、随时续跑**（暂停即落盘）；
- 日常使用几乎零额外成本：两层增量去重（文件没改不读、内容没变不嵌），只有真正改动的块会重新计费；
- 检索失败自动回退普通对话模式，不会让你卡在报错上。

**隐私边界**：向量索引只存本地 `appDataDir/rag-index.json`；嵌入请求与 AI 对话一样走应用内置的 Rust 代理，渲染层不直连外网，CSP 安全策略未放宽。发送给嵌入服务的只有分块文本——这是该功能工作的必要条件，也是它默认关闭、需要你显式开启的原因。

## 你的数据在哪里

| 数据 | 位置 | 联网？ |
| --- | --- | --- |
| 全库索引（标题/双链/标签/闪卡） | 仅内存 | 从不 |
| 闪卡复习进度 | `appDataDir/review-state.json` | 从不 |
| .bib 文献库 | 你选择的路径，只读 | 从不 |

| AI 对话 | — | 你配置的模型服务 |

## 五分钟上手

1. 打开一个工作区文件夹，等右下角索引完成（千篇级约几秒）；
2. **Ctrl+P** 感受全库秒开；
3. 随便找两篇笔记，输入 `[[` 体验双链，去侧栏「链接」页看反链；
4. （写论文的人）设置 → 知识功能 → 选一个 .bib → 选中文字 → 工具栏「@」插一条引用，文末写 `# References`；
5. （学习者）选中一段概念解释 → 「卡」做成闪卡 → 菜单「视图 → 复习闪卡」完成第一次复习；
6. （可选）需要全库问答时，在设置里开启 RAG 并配置嵌入模型。

## 诚实的边界

- 图表编号与引用编号在**编辑器内不实时刷新**（编辑器显示 chip/预览形态，编号在静态渲染与导出中生效）——因为语法解析不随每一次键入重跑，实时编号必然过期；
- LaTeX 导出的 .tex 面向 XeLaTeX + ctexart，本地编译需相应环境（推荐直接用 Overleaf）；
- RAG 的回答质量取决于你的嵌入模型与笔记质量；中文笔记建议搭配中文向量化效果好的嵌入服务；
- 所有 AI 功能（改写做卡、全库问答）都需要你已配置对话/嵌入模型，且做卡结果永远经人工确认才会写入笔记。

## 1. 关键发现：plugin-shell 2.3.5 的 open 真实闸门（风险 A 落地版）

任务书 §七 风险 A 预判「shell:allow-open 的 path scope 条目在真机上不放行 file 打开」，M1 期间经
Rust 源码阅读**证实为确定性事实**（非概率风险），且不止影响新增条目：

1. **capability allow 条目不参与 open 值校验**。tauri-plugin-shell 2.3.5 的
   `OpenScope::open`（`src/scope.rs:202`）只认一个正则；该正则来自
   `tauri.conf.json > plugins.shell.open`（`src/config.rs` 的
   `ShellAllowlistOpen`，`src/lib.rs:147` `open_scope()`）。autogenerated 权限
   文档对 `shell:allow-open` 的描述即「Enables the open command **without any
   pre-configured scope**」。capability 里现存的 `{url:...}` 条目同样是惰性的
   （声明性存在）。
2. **缺省正则拒绝本地路径**：`^((mailto:\w+)|(tel:\w+)|(https?://\w+)).+`——
   `C:\…\print\x.html` 不匹配，`shellOpen` 必被 `Error::Validation` 拒绝。若只按
   任务书加 capability 条目，M1 手测第 1 步（openExternal 临时 HTML）必失败，
   即触发预案 A 的 Rust 改动。
3. **处置（零 Rust、零 npm）**：`tauri.conf.json` 新增
   `plugins.shell.open` 正则——放行 Windows 盘符（`C:\`/`C:/`）、UNC
   （`\\server\…`）、列名 POSIX 绝对路径（`/Users|home|mnt|media|tmp|opt|var/…`）
   与原有 URL 族；拒绝 flag 串（`--enable-debugging`、`-i`、`/R`——config.rs
   文档警告的注入形态，绝对路径前缀要求天然中和）、相对路径与 `file:` scheme。
   放行面脚本验证 **ALL PASS**（13 用例：9 放行 4 拒绝，含 UNC/POSIX/URL/flag/
   相对路径各形态）。capability 的 `{ "path": "$APPDATA/**" }` 条目按任务书照加
   （对 tauri-plugin-opener 形态的将来迁移是正确写法，作为 scope 声明保留）。
4. **顺带修复的潜在缺陷**：HN 轮 HtmlNoteView 顶栏「用系统浏览器打开」在桌面
   端传本地路径给 openExternal——受同一缺省正则影响，此前点击会走
   `.catch → 「打开失败」`。新正则下该按钮恢复预期行为（属既有功能修复，
   未扩大本轮范围，仅一行配置带来的自然结果）。

安全面说明：正则将 JS 可达的 openExternal 从「仅 URL」放宽到「URL + 绝对本
地路径」。评估：应用 CSP `script-src 'self'`、webview 内容全部为本仓代码，
openExternal 的既有调用面（链接/笔记视图按钮/打印）全部传用户文件路径；绝
对路径要求（盘符/双反斜杠/列名根）排除 flag 注入形态。与预案 A（新增 Rust
命令 + opener 插件）相比权限面更小（不动 capabilities、不加依赖）。

## 5. 已知边界（按任务书非目标/风险预案留档）

- **超大文档浏览器通道**（风险 B）：1MB+ md 的 KaTeX 膨胀（~15×）在浏览器
  打开可能卡顿——设置面板 hint 与本报告均已文档化「超大文档建议 PDF 通道」
  （pdf 管线分块光栅已消化该档位）；不做页数预估告警；
- **默认关联异常**（风险 C）：用户 .html 关联到非浏览器（编辑器等）时
  openExternal 打开的不是浏览器——不防御，系统级打印契约本就依赖默认关联；
- **临时目录被清理/拦截**（风险 D）：写入/打开抛错 → doPrint catch →
  toast「打印失败」+ 原因弹窗（铁律 5），不静默；
- **docx 版式**：mammoth 链按 mditor 样式（与 DE 轮编辑态同一保真边界），
  原版式打印引导用户在 Word 中打开原文件（文案已明示）；
- **预案 A 未启用**：plugin-shell 正则方案已验证可行（§1），Rust 透传命令
  不需要；若未来升级 tauri-plugin-opener，capability 的 path 条目即为正确
  scope 形态，迁移零负债。
